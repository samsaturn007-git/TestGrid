# Security, Testing and Operational Acceptance Strategy — v2

## Non-negotiable safe execution boundary

1. **Nothing executable comes from users.** In core scope there is no arbitrary JavaScript, test script, Dockerfile, shell command, Git URL, target URL, regex or Playwright flag from any external user.
2. **Suites come only from the checked-in manifest** and run only against allowlisted demo origins, chosen through `baseUrlRef`. The allowlist is enforced in the worker *and* the API; hiding UI inputs is not enough.
3. **Browser processes run constrained:**
   - non-root, with reduced Linux capabilities and a read-only root filesystem where possible;
   - CPU, memory, pids and time limits;
   - internal-only networking, no Docker socket, and no cloud credentials unless the BrowserStack executor is enabled.
   - Document platform constraints honestly.
4. **Nothing internal is public.** API worker port, queue, DB, artifact storage and observability stay off public ingress. The public demo is a static, read-only snapshot.
5. **No credentials anywhere they could be exposed:** not in the repo, logs, traces, spans, browser snapshots, exception JSON, CI artifacts or screenshots. `.env.example` holds placeholders only.
6. **Every input is validated:** `suiteKey`, engine, profile key, fixture mode (local only), string lengths, unknown fields, MIME types, artifact sizes and malformed JSON. Use prepared statements or an ORM.
7. **No SSRF, path traversal, symlink following or unrestricted downloads.** Artifact keys are generated by the server.
8. **No escape hatch from the gate.** Quarantine and policy changes need a scope, a reason and an expiry, and every one is audited.
9. **Chaos and fixture controls are local-only.** They're refused at startup in any other profile.
10. **Competitors are reference material.** Never copy their branding or proprietary code.

## Threat model

| Threat | Attack path | Mitigation / test |
|---|---|---|
| Remote code execution | Uploaded tests, command concatenation, client-supplied grep or flags | Manifest suite IDs, typed argument builder, `shell: false`, grep built from manifest tags only |
| SSRF | Arbitrary target URL | No URL fields; `baseUrlRef` allowlist; internal network |
| Secrets disclosure | BrowserStack key, tokens in logs, traces or spans | Runtime injection, a redactor in worker and API, span-attribute redaction, canary scans (SEC-002) |
| Unauthorised artifact read | Guessed artifact UUID | Scoped tokens, short-lived HMAC links, private storage (ART-003) |
| Forged worker completion | Fake callback | Service token on a separate port, lease token hash, constant-time compare, generation check |
| Duplicate or late callbacks | Broker redelivery, zombie worker | Idempotent completion key, immutable attempts, `410` on stale lease (Q-005, CHAOS-003) |
| Gate bypass | Abusing quarantine or editing the policy | Scopes, expiry ≤ 30 days, `maxActive` cap, audit, `QUARANTINED_FAIL` always reported (QUA-001/002) |
| Fork PR attack | Malicious PR reading secrets | `pull_request` trigger only, `contents: read`, no secrets needed, SHA-pinned actions |
| Resource exhaustion | Job floods, SSE floods | Rate limits, global session cap, emitter cap, bounded artifacts and timeouts |
| Chaos misuse | Fault hooks enabled outside local | Startup refusal test (CHAOS-004) |
| Supply chain | npm, Maven or image changes | Lockfiles, pinned images, Dependabot, Trivy, dependency audit, SBOM |

## Test pyramid

- **Unit:**
  - Java: state transitions, aggregate truth table, idempotency hash, fingerprint normalisation (`fp_v1`, CONFLICT_REGISTER N28), quality rules, schedulers.
  - TypeScript: manifest parser, argument builder, reporter mapping, redactor, bin-packing, stack-frame extraction.
  - React: StatusBadge and hooks.
- **Property:** seeded JUnit generators for normalisation idempotence (PRD-07; jqwik has no JUnit 6 release, CONFLICT_REGISTER N28); jqwik (Java) for scheduler fairness and transitions and fast-check (TypeScript) for shard coverage, if their versions check out when those PRDs start.
- **Contract:** OpenAPI drift check, completion JSON schema, manifest JSON Schema, BrowserStack HTTP mock.
- **Integration:** Testcontainers with Postgres and RabbitMQ for the outbox, dispatcher, leases, duplicates, reaper, cancel races and SSE replay.
- **End-to-end:** demo-shop → worker → DB → dashboard on three engines. The dashboard itself is tested with Playwright.
- **Chaos:** drills D1–D10 with the I1–I9 validator, at least 10 repeats each (PRD-10).
- **Performance:** paired scheduler and sharding benchmarks with at least 5 trials per cell; k6 API baselines; NoopExecutor orchestration throughput.

## CI gate security (PRD-08)

The `testgrid-gate` workflow runs TestGrid inside the GitHub runner and gates the PR on its own quality evaluation. What keeps that safe:

- **Trigger.** `pull_request` only, never `pull_request_target`. A fork's PR runs the fork's code with GitHub's read-only token and no repository secrets; `pull_request_target` would run with the base repository's secrets and a write token, which is how CI secrets usually leak. GitHub also holds first-time contributors' runs until a maintainer approves them.
- **No secrets at all.** The CI token is generated per job (`openssl rand -hex 32`), masked with `::add-mask::`, given to the API through `.env` and to the CLI as `TESTGRID_TOKEN`, and thrown away with the runner. A fork has nothing to exfiltrate, and nothing has to be stored in the repository's settings.
- **Least privilege.** `permissions: contents: read` at the top, and no job widens it. `actions/checkout` runs with `persist-credentials: false`, so the token isn't left in `.git/config` for later steps.
- **Pinned actions.** Every `uses:` is a 40-hex commit SHA, re-checked against the action's release (docs/VERSIONS.md §1.1); a tag can be moved, a commit can't.
- **No script injection.** No `${{ github.event.* }}` or `${{ inputs.* }}` inside a `run:` script, where a crafted branch name or PR title would become shell; the `workflow_dispatch` input is a choice list passed through `env:`.
- **Manifest only.** The CLI and the API accept suite keys and enums, never URLs, paths, flags or code (ADR-003): `--suite not-in-the-manifest` is `422 unknown-suite`, exit 3. What a PR *can* change is the repository itself, including the manifest and the specs; that code runs only in GitHub's throwaway sandbox with the read-only token.
- **Nothing published.** Compose binds every port to `127.0.0.1` of a runner that is discarded; uploaded artifacts are the run's own reports, screenshots, traces and logs, which the worker redacts (PRD-06).
- **Gate bypass.** The CI token's scopes (`runs:write runs:read quality:read`) can't change the policy or create quarantines (`403`). Quarantines need a reason, expire within 30 days, are capped by the policy, audited, and always reported as `QUARANTINED_FAIL`.

`scripts/workflow-audit.sh` (`make workflow-audit`, in `ci.yml`) fails a workflow that breaks the trigger, permission, pinning, credential or run-script rules. `gitleaks git` over the full history is clean; the six reviewed false positives are listed by fingerprint in `.gitleaksignore` (PRD-12 adds gitleaks to CI, SEC-003).

## Release requirements

- No unresolved critical or high vulnerabilities in exposed services.
- No swallowed exceptions that produce a false `PASSED`.
- Results and metrics come from recorded inputs, never typed in by hand.
- The final report states the environment: CPU, RAM, OS and architecture, Docker, worker count, Playwright and browser versions, suite revision, benchmark seed.
- Every PRD evidence file contains test commands, real output, failure cases, screenshot or log pointers, known limitations and the developer's explanation.
